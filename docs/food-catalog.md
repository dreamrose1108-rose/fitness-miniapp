# 食物库来源与同步

当前内置公共库：2,330 条去重条目（原始合并 2,380 条）。运行时另合并数据库公共增量和当前账号自定义食物，因此页面数量可能更大。本轮实测账号同步 2,382 条。

## 来源与限制

- 保留原云端 298 条公共食物参考值，未改写历史饮食记录。
- 补充卫生福利部食品药物管理署《食品营养成份资料库（2015版）》2,082 条，来自 https://github.com/hanksudo/food-nutrition-data 的原始数据镜像。
- 官方资料入口：https://data.gov.tw/dataset/8543 。授权：政府资料开放授权条款第1版 https://data.gov.tw/license 。本项目经简体转换、分类、字段选择与去重，属于衍生整理，并非机构认可的产品。
- 2026-11-24 尝试官方最新 ZIP 下载时连接失败，因此采用标明版本的2015历史数据，不宣称最新版。来源版本、获取时间和原始 SHA-256 记录在 shared/food-catalog/catalog.json 的 meta 中。
- 来源数值按每100克可食部分；保留已有条目每100毫升单位。未将100g擅自改为100ml；生熟、带皮去皮和菜品名称不互相替换。
- 使用原数据“热量-成分值(kcal)”、粗蛋白、粗脂肪、总碳水等字段，不重新按4/4/9推导热量。缺测营养素保持缺失。调合植物油原始脂肪100.3g/100g超出范围，暂不采用该字段并保留说明。
- 品牌、外卖配方及所有地方菜不可能全部覆盖；不把未核实菜谱或AI估算加入公共事实库。可用个人自定义补充。

## 单一数据源

shared/food-catalog/catalog.json 为公共版本源；index.js 为共同的简繁、别名、去重、排序和分页规则。
运行 `node scripts/sync-food-catalog.cjs`，生成小程序、foodLib、aiCoach、server/aiCoach副本。小程序生成显式JS模块，避免微信不支持目录及JSON require。修改公共库后必须同步构建、测试、部署两个云函数，再生成前端预览。

food-service.js 将数据库公共增量与版本库合并；自定义查询强制ownerOpenid隔离，不返回ownerOpenid。数据库暂不可用时公共内置库仍可查询。AI search_food 与 foodLib 使用同一个服务，响应含单位和来源，不将搜索自动写入饮食记录。

客户端进入饮食页请求catalog完整快照，保留账号分区缓存 `foodCatalog:v1:<openid>`；离线使用该账号缓存和内置库。缓存失败不影响当前页面。切换账号和迟到响应有隔离校验。搜索在本机立即完成，100条一页并支持加载更多；不再因先取100条而误报不存在。模板/营养目标与旧饮食记录不做数据迁移。
