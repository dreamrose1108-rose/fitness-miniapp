# 已保存饮食记录的份量编辑

点击饮食记录后复用份量弹窗，可编辑数量、基础克/毫升或匹配的家用单位，实时重算热量和三大营养素。保存走record.updateDiet原地UPDATE，不再先删除再新增，保持原id、日期、餐次、照片、来源和创建时间。

以原记录的热量与营养素作为基准，不因新食物库版本而重算历史营养密度。第一次修改保存不可变portionBasis，后续修改一直从该基准计算，避免反复缩放造成舍入漂移。普通食物用同一套家用份量规则；拍照识别整餐支持克与“份（原餐食）”，按比例调整每项食物及整餐总值，不把混合菜误认成单个食材。

前端仅提交id、原revision、quantity、portionId。服务端按本人原记录重算，拒绝无效单位、无效数量、超量及过期revision，UPDATE条件再次校验revision防止并发覆盖。失败保留旧记录与输入，不删除照片。

教练历史卡片关联记录若后来被编辑，会提示“以饮食记录为准”，不将旧的计算卡片当作最新摄入数据。

24项相关测试通过：数量/单位换算、宏量营养素同步、重复编辑无漂移、拍照整餐子项同比缩放、账号隔离、并发版本校验、失败不丢原记录。

云端SQL桥接可能不返回UPDATE的RETURNING行，因此更新写入唯一editRequestId后再按本人记录与该标识读取确认，不能仅凭空返回值误判修改失败。已补该回归用例，相关测试共25项通过。

真实云端验证：测试饺子记录保持同一id，6个→3个为75g/174kcal/蛋白质5.25g，改为4个为100g/232kcal/蛋白质7g；保存后弹窗关闭、编辑锁释放、刷新后值一致。测试记录已清理，真实拍照午餐仍416kcal且照片保留，全天总量恢复666kcal。两种主题已检查。

## 照片餐食逐项编辑（2026-11-24）
- 饮食记录的照片餐食打开“逐项修改餐食”，每道食物分别输入数量、选择克/支持的家用单位/原识别份量。
- 原识别份量始终对应首次识别的该食物重量，可输入0.5份。单位重量是估算，原AI营养密度保持不变。
- 合计与保存按钮在食物滚动列表之外，猫咪、森林主题均复核。无效数量禁用提交，失败保留输入。
- updateDiet 接收 itemEdits（index、portionId、quantity），根据当前用户拥有的原记录重算；检查列表完整性与编辑版本，一次写入明细、重量、热量和营养素。
- 保留照片、餐次、日期和记录ID；旧版按整餐缩放过的记录也可逐项编辑。
- 局部回归：record-editor、diet、coach-meal-status、meal-photo；实际照片仅用于界面预览与取消，未修改用户记录。
